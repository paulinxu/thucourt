# 技术选型（中文整理）

| 层 | 技术 | 用途 |
| --- | --- | --- |
| 后端 | Python 3.12、Django 5.2、DRF | ORM、权限、事务、Admin 和 REST API |
| 前端 | React 19、TypeScript、Vite | 移动端友好的网页和交互页面 |
| 数据库 | SQLite（本地）/ PostgreSQL（生产） | 关系约束、筛选、比赛事务 |
| 异步 | Celery + Redis | 视频抽帧、模型请求、通知任务 |
| 媒体 | Pillow、FFmpeg | 图片解码清理、视频元数据和最多八帧抽取 |
| 认证 | Django Session、CSRF、微信 OAuth | 不把会话密钥放在浏览器 localStorage |
| 质量 | pytest-django、Ruff、TypeScript、npm audit | 后端规则、格式、前端构建和依赖审计 |
| 部署 | Docker Compose、Nginx、Gunicorn | API、worker、PostgreSQL、Redis 和静态网页 |

## AI 模型适配

`AI_PROVIDER=demo` 使用确定性的本地规则模板，适合没有外部额度时的演示。`AI_PROVIDER=remote` 通过服务端 HTTPS 发送结构化上下文，模型名、地址和密钥由环境变量提供。模型不能执行 SQL、shell、文件系统或消息工具；它只能读取服务端已经完成权限检查的五类证据：本人资料、本人反馈、本人确认比赛、本人历史计划和本人媒体观察。

远程模式按用户每日次数和项目全局调用次数限额，网络请求最多两次重试；权限失败不重试。模型返回结果必须通过 JSON Schema、时长合计、证据 ID 所有权和边界校验，前端的显式保存动作才会写入 `TrainingPlan`。
