# 系统架构（中文整理）

浏览器通过同源 HTTPS 访问 React + TypeScript 页面和 Django REST API。Django 使用 PostgreSQL 保存账户、需求、比赛、消息和教练记录；Redis/Celery 负责媒体处理和远程模型任务；私有文件系统或 S3 兼容对象存储保存照片、视频及派生文件。浏览器不会接触模型密钥。

## 模块

- **账户**：Django Session、CSRF、微信 OAuth 适配、个人资料和管理员身份审核。
- **场地集市**：买场、转场、换场和可筛选的列表/网格；创建者可删除自己所有状态的需求。
- **约球**：绑定区域、日期、时间和具体场地，带单/双打、缺少人数和水平范围。
- **社交**：好友关系只决定能否评价；任何已认证学生可消息联系；支持拉黑和通知。
- **比赛**：结构化比分、确认、不可更正的官方历史和单/双打独立排名。
- **AI 教练**：服务端白名单证据工具、照片/视频观察、计划校验、私有保存和数据删除。
- **管理**：Django Admin 审核身份，配置场地区域与时段，查看只读比赛记录。

## 核心数据规则

紫荆 14 片、北馆 4 片；默认 08:00–22:00 的 14 个一小时格；展示上海时区今天和未来三天。买卖网格是 14 行 × 14/4 列，约球网格是 14 行 × 1 列。只有 active 且未开始的需求进入发现结果。

积分初始为单打 1000、双打 1000。最终确认一次性写入每位参赛者的唯一 `RatingEvent`：胜者 +10，负者 −10，平局 0；只影响对应项目。匿名行为评分不等同技术积分，目标玩家以外的人看不到技术反馈作者。

## 生产边界

生产必须使用随机 `SECRET_KEY`、HTTPS、安全 Cookie、PostgreSQL、Redis 和真实的人工审核流程；`DEMO_MODE` 必须关闭。私有原始媒体默认保留 30 天，清理命令不会删除已保存的历史训练计划。
